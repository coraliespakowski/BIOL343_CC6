Question 4: Which two predictors are collinear, and why would you expect that from how the regions are defined? Does your correlation table show it? Compare the estimates, standard errors and p-values for region and longitude across the three models. Answer:

The two predictors that are likely collinear are region and longitude. This is expected because the Central and East regions are geographically separated, meaning that longitude is likely strongly associated with which region a site belongs to. The correlation table does not directly show this relationship because region is categorical and was not included in the correlation analysis.

However, the substantial changes in the estimates suggest possible multicollinearity, which can make the individual coefficients unstable.

I would keep region and remove longitude because region is more directly related to the biological hypothesis being investigated and is easier to interpret.

Question 5: Do any of the three models support hypothesis 3? Suppose damage had no effect at all on any of the three measures. What is the probability that at least one of three independent tests gives p < 0.05 by chance? What does that mean for a study that tests many responses or many predictors?

Answer:

None of the three models supports Hypothesis 3 because none of the relationships between beetle damage and the plant characteristics (stem density, stem height, and inflorescence number) was statistically significant. All three p-values were greater than 0.05.

If damage had no effect on any of the three measures and the tests were independent, the probability of obtaining at least one significant result by chance would be 1 - (0.95)³ = 0.1426, or approximately 14.26%. What this means is that for a study that tests many responses/predictors, there is an inflation of type I errors (false positives). Therefore, studies that test many responses or predictors should consider using multiple-testing corrections, such as the Bonferroni or Holm correction, to reduce the risk of incorrectly identifying significant relationships.

6 How good is a quick field check?

A manager suggests a cheap way to tell whether beetles were released at a site without checking the records: call it a release site if its damage index is 3 or more. Add a column to lythrum_ce with this prediction, and make a table of the predicted against the actual release status. Treating “release” as a positive result, count the true positives, false positives, true negatives and false negatives, and calculate the accuracy, sensitivity, specificity and false discovery rate of the check.

# new prediction column
lythrum_ce <- lythrum_ce %>%
  mutate(predicted_release = ifelse(damage >= 3, "Release", "Nonrelease"))

# table of predicted against actual
table(Predicted = lythrum_ce$predicted_release, Actual = lythrum_ce$release)
##             Actual
## Predicted    Nonrelease Release
##   Nonrelease         24       2
##   Release             7       5
# count true positives, false positives, true negatives, and false negatives
results <- lythrum_ce %>%
  summarise(
    TP = sum(predicted_release == "Release" & release == "Release"),
    FP = sum(predicted_release == "Release" & release == "Nonrelease"),
    TN = sum(predicted_release == "Nonrelease" & release == "Nonrelease"),
    FN = sum(predicted_release == "Nonrelease" & release == "Release")
  )

# calculate accuracy, sensitivity, specificity, and false discovery rate
results <- results %>%
  mutate(
    accuracy = (TP + TN) / (TP + FP + TN + FN),
    sensitivity = TP / (TP + FN),
    specificity = TN / (TN + FP),
    false_discovery_rate = FP / (TP + FP)
  )

# display results
results
##   TP FP TN FN  accuracy sensitivity specificity false_discovery_rate
## 1  5  7 24  2 0.7631579   0.7142857   0.7741935            0.5833333

Question 6: Report the four rates. Why is the false discovery rate so much higher than you might expect from the accuracy? If the manager’s goal is to find every release site so that it can be monitored, should the check be more sensitive or more specific, and which way would you move the threshold of 3?

Answer:

The four classification rates are accuracy, sensitivity, specificity, and false discovery rate, calculated from the confusion matrix. Accuracy measures the overall proportion of correctly classified sites, while the false discovery rate measures the proportion of sites predicted to be release sites that were actually nonrelease sites.

The false discovery rate can be relatively high despite reasonable accuracy because release sites may be less common than nonrelease sites. Therefore, false positives can represent a large proportion of all sites predicted to be release sites, even if most sites overall are classified correctly.

If the manager’s goal is to identify every release site for monitoring, the check should prioritize sensitivity over specificity. High sensitivity reduces the number of false negatives, meaning fewer actual release sites are missed. I would therefore lower the damage threshold from 3. This would classify more sites as release sites, increasing the likelihood of identifying all actual release sites, although it may also increase false positives.
